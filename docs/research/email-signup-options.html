Noisy Studio / Decision note

Release notifications.
Without our own backend.

Three hosted email-list options for the Windows and Linux launch. Researched 13 September 2026. Prices and limits can change.

My recommendation: MailerLite.

Use two provider-managed signup forms, one for Windows and one for Linux. The provider stores subscribers and sends the launch email. Keep our existing page and visual design; connect it using the provider’s supported embed. No database, API server, or secret API key in GitHub Pages.

01 / BEST FIT

MailerLite

A practical starting point for a small release list and occasional announcements.

Pros

  • Embedded forms can add subscribers to selected groups: a natural fit for separate platform waitlists.
  • Visual email editing and campaign management in one service.
  • Free entry tier for validating demand.

Cons

  • The free tier is now only 250 active subscribers and 2,500 emails per month.
  • Sending locks when the free subscriber limit is exceeded; budget for an upgrade before a larger launch.
  • Matching the embed to our design needs a small integration pass.

Choose it if: we want the simplest balanced option.

Pricing and free limits · Embedded forms

02 / LARGE WAITLIST

Brevo

More room for collecting contacts, with a tighter free sending limit.

Pros

  • Free plan lists storage for up to 100,000 contacts.
  • Hosted and embedded signup forms; separate lists can represent Windows and Linux.
  • Collection and email campaigns stay with one provider.

Cons

  • Free sending is capped at 300 emails per day: a 3,000-person launch needs at least ten sending days, or a paid upgrade.
  • Free emails carry Brevo branding.
  • Broader marketing functionality makes it a heavier tool than our immediate needs.

Choose it if: the waitlist may grow quickly and we can pay when it is time to announce.

Plan limits · Free restrictions · Signup forms

03 / MINIMAL NEWSLETTER

Buttondown

A focused alternative if a lightweight newsletter experience matters most.

Pros

  • Documents a plain HTML subscription form that can submit directly from a static website.
  • Writing-focused editor rather than a large marketing workspace.
  • Pricing page advertises the first 100 subscribers free.

Cons

  • Pricing lists tagging and segmentation as a $9/month add-on; relevant to platform-specific notifications.
  • Advanced standalone forms are separately documented as requiring Standard at $29/month.
  • Those plan descriptions are not completely aligned: confirm the exact embed-plus-segmentation cost before choosing it.

Choose it if: simplicity is worth paying for; not my first choice for the cheapest segmented waitlist.

Pricing · Basic HTML embed · Advanced forms and plan requirement

How it works on GitHub Pages

Our email field→Provider signup form→Platform group / list→Launch notification
  1. Create Windows and Linux groups or lists in the chosen service, with one signup form per platform.
  2. Embed the supported public form in both CTA placements. The detected platform chooses the form; collect email only. Use the same platform list in the hero and bottom section.
  3. Let the provider handle confirmation and unsubscribe. Show a successful signup only after its response; retain an understandable error state.
  4. When a platform launches, compose one campaign and select that platform’s list. No GitHub release automation is necessary for the first version.

Configure our sending domain in the service before the announcement. Keep the promise narrow: release notifications, not an unrelated newsletter. Suggested confirmation flow: email confirmation, then a clear “You’re on the list” page.

This is an implementation recommendation, not a connected integration. No accounts were created and no email addresses were collected. We would use the provider’s public form endpoint, not expose an administrative API key. Exact custom styling and success handling should be checked against the selected provider’s generated embed.
